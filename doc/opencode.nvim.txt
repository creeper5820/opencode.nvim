*opencode.nvim*  Host the official OpenCode TUI in Neovim

OpenCode remains the renderer, composer, dialog owner and input owner.  This
plugin starts the official `opencode` terminal UI in a Neovim terminal buffer
and manages its lifecycle, window visibility, selection actions and health
checks.  It is pure Lua and uses no HTTP client, companion process or extra UI.

1. REQUIREMENTS                                    *opencode.nvim-requirements*

- Neovim >= 0.10 (`vim.uv`, terminal buffers, `vim.keymap`).
- The `opencode` CLI on `$PATH`.

==============================================================================
2. SETUP                                                 *opencode.nvim-setup*

With lazy.nvim: >lua
  {
    "creeper5820/opencode.nvim",
    config = function()
      require("opencode").setup()
    end,
  }
<
All options are optional: >lua
  require("opencode").setup({
    cmd = "opencode",
    args = {},
    cwd = nil,
    project = { root = nil },
    session = { continue = false, id = nil, prompt = nil },
    window = {
      layout = "right",       -- right | left | above | below
      size = 80,
      remember_width = true,
    },
    keymaps = {
      toggle = "<leader>oo",
      send_selection = "<leader>os",
      question_selection = "<leader>oq",
    },
    paste = {
      bracketed = true,
      ready_delay = 150,
      submit_delay = 30,
    },
  })
<
For vertical `right`/`left` layouts, `window.remember_width = true` remembers
the actual width you set during this Neovim session and restores it on reopen,
clamped to the current `vim.o.columns`.  No file is written.

==============================================================================
3. COMMANDS                                           *opencode.nvim-commands*

:OpenCode [toggle]             Open or hide the TUI.
:OpenCode open [dir]           Open in dir.
:OpenCode close                Hide the window; keep the process alive.
:OpenCode stop                 Stop the process started by this plugin.
:OpenCode restart [dir]        Stop and start a fresh TUI.
:OpenCode continue [dir]       Start with --continue.
:OpenCode session <id> [dir]   Start or resume a session with --session.
:OpenCode new [dir]            Start without session/continue flags.
:OpenCode submit               Send Enter to the TUI composer.
:OpenCode health               Print health information.

Convenience commands: :OpenCodeToggle, :OpenCodeOpen, :OpenCodeClose,
:OpenCodeStop, :OpenCodeContinue, :OpenCodeSession, :OpenCodeSubmit,
:OpenCodeHealth.

==============================================================================
4. KEYMAPS                                             *opencode.nvim-keymaps*

<leader>oo   Normal   Open or hide the OpenCode TUI.
<leader>os   Visual   Paste formatted selection context; never submits.
<leader>oq   Visual   Open a float, then paste question + context and submit.

Each keymap can be changed or disabled with `false`.  These are global editor
mappings; the plugin installs no Normal-mode mappings in the terminal buffer.

==============================================================================
5. TERMINAL BEHAVIOUR                               *opencode.nvim-terminal*

The TUI runs in one terminal buffer and one window.  While that window is
focused it stays in Terminal mode.  OpenCode receives every key directly,
including text, Enter, Escape, arrows, Alt combinations, the leader key,
multi-key sequences, dialogs, completion and session navigation.

There is no logical composer/session focus, Normal command table, leader
replay, Visual emulation, cursor synchronization or click emulation.

Global Neovim Terminal-mode mappings are shadowed in the OpenCode buffer by a
raw byte forward of their own lhs.  This prevents mappings such as LazyVim's
`t jk` from stealing text.  The forward is plain pass-through and does not
interpret OpenCode commands.

`WinEnter`, `BufEnter`, `BufWinEnter` and `ModeChanged` re-enter Terminal mode
when the OpenCode window is focused.  Hiding/revealing uses ordinary Neovim
terminal window semantics.

==============================================================================
6. SELECTION ACTIONS                               *opencode.nvim-selection*

<leader>os extracts the current Visual selection, formats it as Markdown with a
safe fence and path/line range, opens/focuses the terminal and pastes it into
the composer.  It never submits.

<leader>oq opens an editable Neovim float.  On <C-s> it pastes the question and
context as one bracketed paste, then sends a separate Enter/Submit event after
a short delay.  The float keeps its text on failure and closes on cancellation.
Empty questions are rejected.  Text beginning with `/`, `:` or a key name is
never interpreted as a TUI shortcut because it travels inside a bracketed
paste; the paste terminator is sanitized.

OpenCode owns sessions; the plugin creates or tracks no session ID.

==============================================================================
7. HEALTH                                               *opencode.nvim-health*

:checkhealth opencode and :OpenCodeHealth report Neovim/vim.uv availability,
configuration validity, the OpenCode executable and its --version, and terminal
process/window state.  No network service is required.

==============================================================================
8. TESTING                                             *opencode.nvim-testing*

Unit tests: >sh
  bash tests/run.sh
<
They run in an isolated headless Neovim with temporary HOME/XDG directories,
shada and project under /tmp/opencode.  The terminal smoke test starts an
isolated official TUI with --standalone and stops only that process.

Real tmux end-to-end check: >sh
  python3 tests/e2e/tmux_e2e.py
<
It uses a private tmux socket and isolated Neovim/OpenCode state.  It verifies
native Alt input, native leader combinations, real TUI cursor movement, text
despite a global `t jk` mapping, hide/reveal returning to Terminal mode,
explicit Ctrl-\ Ctrl-n returning to Terminal mode, and remembered vertical
width across close/open.
